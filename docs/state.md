## Где мы сейчас

Этот репозиторий используется агентом-комплаенсом ПДн (см. CLAUDE.md — скилл `pdn-compliance`) для сопровождения обработки, хранения и уничтожения персональных данных ООО «ЕС Транс» (сайт es-trans.ru). Ветка `src/` — отдельный, не связанный с ПДн шаблон Б24-дашборда (см. `project-brief.md` — не заполнен, был онбординг в предыдущих сессиях, к задаче ПДн отношения не имеет и в этой сессии не трогался).

Пользователь создал приватный репозиторий `krutko77/security-and-personal-data` и через веб-интерфейс GitHub добавил два файла: `КоАП_ст13.11_ответственность_ПДн.docx` и `ООО "ЕС ТРАНС" документы.zip` (27 docx-документов + пояснительная записка от юрфирмы, редакция 2, актуализирована под 152-ФЗ с изменениями от 01.09.2025). Комплект полностью изучен (распакован с перекодировкой имён cp437→cp866, текст извлечён из XML), сопоставлен с фактическим состоянием сайта es-trans.ru (получен напрямую через curl — WebFetch в этом окружении заблокирован сетевыми ограничениями).

**Итог сопоставления:** сайт уже частично приведён в соответствие комплекту — privacy-policy.html (05.09.2026), cookie-policy.html (04.09.2026), agreement.html (07.09.2026, с поимённо указанными 4 обработчиками — Битрикс24/СКБ Контур/Яндекс/ТаймВэб) актуальны и совпадают с текстами юрфирмы. Все 3 формы сайта (form-customs, form-offer, form-driver) имеют непредзаполненный обязательный чекбокс согласия — старый баг form-driver (прецедент в CLAUDE.md, коммит d6ce470) не воспроизводится. Cookie-баннер с Согласен/Отказаться и localStorage реализован в JS.

Подробности аудита, полная таблица сроков хранения и список незаполненных полей — в памяти агента: `~/.claude/projects/-home-my-workspace-security-and-personal-data/memory/es_trans_pdn_doc_package.md` и `company_es_trans.md`.

**2026-09-24:** сопровождение технического соответствия es-trans.ru законодательству о ПДн полностью перешло в этот проект (ранее вело `website-customizer`). Вся история технических патчей сайта (cookie-баннер, гейтинг Метрики/Bitrix24/Карт, серверная фиксация согласия, найденные и закрытые баги согласия в формах, все аудиты 152-ФЗ по коду) перенесена без сокращений в [docs/es-trans-technical-history.md](./es-trans-technical-history.md) — читать при вопросах про конкретный патч/баг/дату. `website-customizer` остаётся отдельным репозиторием для будущих правок вёрстки/кода, но не ведёт больше комплаенс-документацию по ПДн.

В этой сессии (2026-09-23) пользователь дополнил `CLAUDE.md`: добавлен раздел «КЛОДУ: Прочитай это первым делом» с инструкцией — в начале новой сессии читать только `docs/state.md` (не открывать `last-session.md`/`handoff.md` автоматически, чтобы экономить контекст; открывать их только по явному запросу, при нехватке контекста или при передаче сессии). Также был добавлен, а затем по просьбе пользователя удалён раздел «Кеширование» (Map/JSON, папка `data/`) — он не подошёл для этого проекта (нет тяжёлых отчётов для программного кеширования, только markdown и docx).

## Сейчас в работе

**ПДн-комплаенс (основная задача проекта)** — по-прежнему ждём от владельца компании решения по трём организационным вопросам (не технические, не могут быть решены агентом без ввода пользователя):
1. Кто ответственный за организацию обработки ПДн — директор Попов С.А. (де-факто уже фигурирует во всех документах) или другой сотрудник (ст. 22.1 152-ФЗ разрешает оба варианта).
2. ФИО сотрудников для перечня лиц, допущенных к обработке ПДн (нужно минимум 3-4 человека: бухгалтер/кадровик, менеджер/логист, ответственный за сайт).
3. Нестыковка email: `info@es-trans.pro` на contacts.html vs `policy@es-trans.ru` в Политике ПДн — какой реально мониторится в срок 10 рабочих дней.

**Смежная задача, выполнена в этой сессии (2026-09-29) — вне сферы ПДн:** пользователь (штатный Битрикс24-интегратор ЕС Транс) попросил помощи с security review своих вайбкодинг-приложений вокруг корпоративного Bitrix24. Это не ПДн-комплаенс, поэтому результат вынесен в **отдельный новый репозиторий** `/home/my_workspace/es-trans-app-security` — см. подробности там (`docs/state.md` этого нового репозитория). Кратко: проведено обследование 4 продакшн-приложений (`es-trans-cargo`, `es-trans_repairs`, `es-trans_orders-and-transportation`, `es-trans_integration_A1TRACK`), написан стандарт безопасности (`docs/standard.md`, 8 пунктов MUST/SHOULD), создан агент-ревьюер. Найдена и передана пользователю (не исправлена автоматически) критичная находка: захардкоженный root-пароль VPS в `es-trans_orders-and-transportation/deploy.sh:10`. Этот репозиторий (`security-and-personal-data`) дальше эту задачу не ведёт — она полностью перешла в `es-trans-app-security`, аналогично тому, как техническая история сайта в 2026-09-24 перешла сюда из `website-customizer`.

**Также в конце сессии (2026-09-29):** по просьбе пользователя в `/home/my_workspace/es-trans-app-security/.claude/` скопированы `commands/` (decision/end/handoff/log) и `settings.local.json` из этого проекта. В новом репозитории они ещё не закоммичены; тексты команд заточены под ПДн-проект и требуют проверки; права в `settings.local.json` широкие (`Bash(*)`, `mcp__*`).
